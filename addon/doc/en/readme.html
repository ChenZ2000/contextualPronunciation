Context-aware Pronunciation 0.7.4

0.7.4: First public repository release; stable API declaration: NVDA 2026.2. Source, releases and support.

New in 0.7.3: Resolve spatial noun and coordinated predicate edges, support bare multirow labels, and recheck residual target readings after dictionaries before speech is queued. 1,154 targeted grammar cases. Existing settings, character mode and command boundaries remain effective.

New in 0.7.0: Productive 重 + predicate analysis, nested and coordinated modifiers, and explicit 把/将 preposed arguments work by default. The 357,293 lexical candidates retain source evidence, not an accuracy guarantee. Parsing has a 512-character / 256-token window, depth 16 and analysis/item work budgets. Unknown or over-budget constructions abstain. This is not complete Chinese semantic understanding or zero latency. Dynamic annotations retain original text and do not replace the static braille table.

This NVDA 2026.2 / 2026.3beta2 add-on applies Mandarin contextual pronunciation rules globally to every synthesizer, voice and language tag. There are no engine or voice whitelists and no private WorldVoice adapter. The public speech-sequence filter analyzes original text; a pre_speechQueued listener checks residual target readings after dictionaries and symbols. The stable manifest declares NVDA 2026.2; beta2 is an additional development test target.

Install and settings

Install the 0.7.4 nvda-addon and restart NVDA when prompted. Enable contextual rewriting and Chinese polyphones in the add-on settings. Bounded lexical-semantic parsing composes food/material objects, possessors and local relative clauses. Version 0.6.1 fixes 盛液体 / 盛装液体 through audited sememe inheritance, conditional attire protection, contextual morphology, classifier disambiguation and typed relative attachment. These three reviewed argument frames work without the experimental phrase lexicon. Existing explicit rules and user keep decisions remain authoritative. An old Off preference remains disabled until you re-enable Chinese corrections.

With the experimental lexicon enabled, crossing-reading locks also enforce an accepted dictionary default when another reading-bearing word crosses its selected boundary. 降调音频 was already segmented as 降调 / 音频; diào was incorrectly assumed to need no output enforcement. The new generic mechanism preserves that decision against the competing 调音 edge. 调音师 still takes tiáo. No complete 降调音频 exception or engine-specific gate was added.

The extended phrase lexicon is experimental and off by default. It may improve coverage but can also misread ambiguous contexts. Global Mandarin rules also affect Chinese characters tagged as English, Cantonese, Japanese or traditional Chinese; they cannot add Mandarin support to a voice. Character/spelling mode remains unchanged. The add-on does not switch voices or alter original documents.

WorldVoice 6.2

WorldVoice's public dictionary filter runs first. Its dictionary output can therefore be normalized once by this add-on in both language-detection modes. Unicode substitutions have different ordering: before-mode substitutions precede our rules; after-mode substitutions may receive an already-rewritten character. Use a local keep rule if you need the original character preserved for a later stage. No installed WorldVoice files or user dictionaries are modified.

Installed 6.2 source-chain tests use the real pipeline and substitute voices, including containment, syntax and crossing locks in both dictionary orders. Separately, the user confirmed listening to earlier releases with WorldVoice 6.2 and VE:Ting-Ting. This is not live audio acceptance of all new 0.6.1 contexts or other voices.

Data and contribution

The offline source database contains 131,436 attributed CC-CEDICT/KFCD records. The compiled optional lexicon contains 183,244 exact source-authored simplified/traditional headwords: 147,598 annotatable and 35,646 blockers. Of the non-default targets, 623 characters meet the speech-candidate policy in 7,903 headwords. These counts measure candidates, not pronunciation accuracy. Unknown positions remain unknown; conflicting sources do not silently choose the first pronunciation.

Version 0.5.0 adds bounded unigram lattice adjudication for disputed spans only. Weights come from the same pinned cppjieba dictionary as NVDA beta2; no private NVDA APIs or shared user dictionaries are accessed. Agreed words and blockers are preserved. Maximum word length is 32, disagreement-island length 96, and likelihood margin log(16); this is not a calibrated pronunciation probability or neural semantic model. The Unihan ledger inventories 8,372 characters / 19,570 reading pairs, including historic/regional variants; 2,879 characters have phrase evidence. The user-suggested cc-table remains reference-only. See the 0.5.0 design and evidence.

Use templates such as 仙[乐:yuè] or [盛:chéng]{number}{container}. 仙[乐:keep] preserves the target locally. Templates have bounded syntax and cannot execute Python or arbitrary regular expressions. See the Chinese contribution guide and design report.

Braille and limitations

OpenHowNet contributes 215,831 retained sense records and 117,464 lexical heads, with 2,760 unanimous food heads, 4,455 containment-material heads and 451 container heads; these classes may overlap. There are 147 ambiguous food and 291 ambiguous material heads. These are semantic features, not pronunciation accuracy. The official taxonomy is projected offline; only runtime JSON features are installed, not the API, executable pickles, BabelNet or a neural model. Static POS alternatives and bounded parsing are not full dependency parsing or universal semantic understanding. See the 0.6.1 fixes and scope.

The shared annotation API includes new syntax decisions and original offsets; the optional static Liblouis table does NOT dynamically consume them. No new claim of complete GF 0019-2018 translation is made.

The optional experimental Chinese common braille 2018 table derives 12,057 finite context combinations from reviewed templates, not individually reviewed words. Factored equivalent alternatives and three base-word conditions compile to 455 match instructions. Version 0.6.1 only adds static preservation of 盛裝; it does not compile the dynamic containment grammar. The native regression compares against an uncompressed reference table, including cell routing; it also measures warm translation cost. Single ASCII word separators from beta CWS are accepted without crossing newlines. Select the table manually. Dynamic numeric rules, the extended lexicon and custom speech settings do not synchronize into it. Full-tone annotations retain original code-point/UTF-16 offsets but do not replace the standard's tone omissions. Computer-braille expansion at the cursor intentionally bypasses contextual translation. See the 0.5.1 scope and limitations.

Speech uses temporary homophones, not a universal phoneme API. Speech Viewer may show these characters. Source documents, clipboard text and accessibility objects remain unchanged. Acoustic probes and bounded performance gates do not certify every voice, tone, arbitrary sentence or zero end-to-end delay. Further listening, live WorldVoice and braille hardware acceptance remain necessary.
