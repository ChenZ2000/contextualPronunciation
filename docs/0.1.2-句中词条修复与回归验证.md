# 0.1.2：句中词条漏改的根因与修复

本版修复“我给孩子盛汤之后盛饭”“盛饭盛汤很好”等句中漏改，不针对每个句子添加特例。安装包为 `dist/contextualPronunciation-0.1.2.nvda-addon`；精确的最终验证时间、计数、包大小和 SHA-256 记录在 `artifacts/release-verification.json`。

## 1. 已复现的根因

旧版 `cheng-serving-object-bounded` 将盛汤、盛饭、盛水、盛粥、盛菜、盛酒、盛药、盛茶、盛面、盛米、盛土、盛沙这 12 个动宾词设置为 `rightBoundary: true`。这要求词后是句末、空白、标点或符号；“之后”“很好”等普通正文不满足条件。

以下是修改前直接执行 0.1.1 规则所得的临时语音文本，不是凭听感猜测：

| 原文 | 0.1.1 实际输出 | 0.1.2 Ting-Ting 输出 |
|---|---|---|
| 我给孩子盛饭之后盛汤 | 我给孩子盛饭之后成汤 | 我给孩子呈饭之后呈汤 |
| 我给孩子盛汤之后盛饭 | 我给孩子盛汤之后成饭 | 我给孩子呈汤之后呈饭 |
| 盛饭盛汤 | 盛饭成汤 | 呈饭呈汤 |
| 盛饭盛汤很好 | 盛饭盛汤很好 | 呈饭呈汤很好 |

因此并非程序随机回退、缓存串位或只处理一次“盛”。旧版逐字循环本来就会处理每个目标字，但中间词条被条件过滤掉了；部分漏改字由 VE 恰好读对，掩盖了插件覆盖不完整的问题。

“盛饭、盛汤”在用容器装东西的动词意义下读 chéng；“丰盛”等读 shèng。词义依据见 [教育部《重编国语辞典修订本》“盛”](https://dict.revised.moe.edu.tw/dictView.jsp?ID=8518&q=1&word=%E7%9B%9B)。

## 2. 运行代码保持精简

- 取消上述明确词条的右分隔符要求，使用引擎已有的句中词条匹配能力。没有新增后缀白名单、分词器、逐句缓存或正则补丁。
- 保持“先在原文上逐目标字判定，再统一生成临时语音文本”的既有流程；一处保护或替换不会改变另一处的匹配上下文。
- 保留盛开、旺盛、盛汤姆、盛饭店、盛水准等保护规则，补充丰盛，防止把“丰盛饭菜”跨词误判成“盛饭”。
- 历史规则 ID 保持不变，避免破坏用户已有的禁用项；显式用户规则和 `keep` 仍然优先。
- Unicode 分隔符判断不变。行号、行数等真正需要边界的结构继续使用它，普通汉字不会被错误地提升为“标点”。

本版没有新增运行时模块、回调注册或语音过滤层。测试、编译、声学审计与显示恢复包装均是开发工具，不进入安装包。

## 3. 声音适配与分类分离

扩展声学回归中发现：旧同音替代“成”与“药”连用会形成现有词语“成药”。完整音素与“乘药”等锚字相同，但“成”对应的一个音段比锚点短 550 个采样点，整段 PCM 也不同。这不直接证明声调错误，却说明不能把不同字的整段音频差异一概当作误读。

本版没有为“药”再加一条运行时分支，而是验证后统一将 **Ting-Ting 的 cheng2 常量映射改为“呈”**。在本次 130 组句中对照中，其完整音素与整段 PCM 均和独立“乘”锚点一致。通用普通话的实验性映射仍为“成”，不把一个声库的结果外推到其他引擎。

默认分类层测试仍可用“成”表达 cheng2；实际声音链路、符号处理和声学测试明确使用 Ting-Ting 配置，并以独立预期“呈”检查，防止误测通用配置。Speech Viewer 或重复最后一条语音可能看到“呈”，原始文档和盲文不变。

## 4. 回归覆盖与门禁

- 原始 4 个句子逐字断言，不允许以“至少发生一次替换”作为通过条件。
- 12 × 12 个动宾词、7 种连接方式、3 种前文、6 种后文，共 18,144 组组合；分别验证通用分类输出和 Ting-Ting 适配输出。
- 句中重复、交换词序、连续词语、正文与符号后缀、保护词混排、用户 keep、旧规则 ID 禁用、幂等性与原始输入不变。
- 明确不跨字符串或语音命令猜测半个词；逐字模式与英语片段继续遵从 NVDA 的原始行为。
- 保留 Unicode 1,114,112 个码位的分隔符分类检查、12 个动宾词的所有 Unicode 符号/空白组合，以及行号和排行结构检查。
- 变异测试将旧 `rightBoundary` 条件放回后，原始 4 例必须全部报错；将旧 Unicode 分类缺陷放回后，9 个报告符号必须全部被结构测试检出。
- 真正的 NVDA `speech.speech.speak` 链路：4 种符号级别、实际 GlobalPlugin、语音命令、字典与符号处理；只截获最终语音队列，不播放声音。
- 本机 VE 离线回归：既有 renderer 11 组 / 33 条、符号 120 组 / 360 条、句中 130 组 / 520 条。句中每组包含原文、旧策略对照、新版输出、独立同音锚；发布要求新版完整音素和整段 PCM 同时一致。
- 编译固定提交的 NVDA 本体并执行上游全套单元测试；屏幕颜色测试保留其原断言和外部效果跳过条件，外层 `finally` 显式恢复颜色状态。跳过不会被记成通过。
- 运行热路径的无文件/网络访问检查、短句和长文本性能门禁、固定字节可复现构建、Windows Git 换行往返与包内布局检查。

发布过程的每个阶段有退出码与日志哈希。规则、声音适配、测试工具或固定语料变动后，旧证据不能用于发布。

## 5. 复现

通用完整入口：

```powershell
python scripts/run_regression.py --native --vocalizer --release
```

本机已准备的 LLVM / ARM64 ATL 环境适配：

```powershell
python scripts/run_regression.py --native --vocalizer --release `
  --llvm-bin vendor/llvm-20.1.8/bin --spectre-atl-fallback
```

本地修改规则后先更新绑定哈希的声学语料；任何独立预期不符会拒绝生成：

```powershell
python tools/generate_final_renderer_fixture.py
python tools/boundary_acoustics.py generate
python tools/sentence_acoustics.py generate
python scripts/run_tests.py
```

完整证据位于 `artifacts/workflow-report.json`、`artifacts/addon-tests.json`、`artifacts/nvda-native-integration.json`、`artifacts/nvda-display-guard.json`、`artifacts/performance-report.json` 和三套声学目录的 `summary.json`。旧包仍保留，部分 0.1.1 发布证据另存于 `artifacts/release-0.1.1-evidence`。

## 6. 验收边界

这次修复的是已知完整动宾词因句中位置而失效的确定性缺陷。不能保证所有未知姓名、孤立多音字、被应用拆断的上下文、用户主动覆盖的规则以及全部声音都百分之百正确；未适配声音仍默认不改写。也不能把有限样本的音频等价当作全部声库或人耳试听认证。

本地性能结果是多轮批量平均耗时的中位数，不是端到端 p99 或绝对零延迟。插件包不含 NVDA 源码、厂商 DLL、声库、离线 WAV 或开发测试脚本；开发流程不安装插件、不改当前 NVDA 配置、不替用户重启读屏。
