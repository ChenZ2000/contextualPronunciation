# 0.7.3：分词边界与合成前读音

本次处理“下边缘”“唱和说”“多行”，并补充语音词典改写之后的检查。它们对应三个不同原因：词典默认读音没有进入语音输出、最长词匹配掩盖并列动词、数量规则遗漏裸量词及“行文”保护误覆盖“行文本”。

## 结构与词典证据

- `下 / 边缘`：从固定版本 OpenHowNet 中投影 118 个具有边部件义的名词，结合方位修饰语识别名词中心词，支持边缘、边框、边界及来源明确的繁体词形。目标“边”输出 biān；单独的“下边”和“边唱边说”不套用这个结构。
- `唱 / 和 / 说`：从 HowNet 中投影 450 个唱、说、诵读等言语动作的动词义，结合右侧独立谓词建立并列关系，允许重新评估跨越“和”的整词匹配。保留“诗人唱和”“唱和着”“附和说法”等完整词或证据不足的情况。该规则有语境歧义边界，不能据此证明所有连续动词都具有唯一分析。
- `多 / 行`：补充裸“多行”和文本、输入、编辑、显示、模式等行列语境；“多行不义”“多行善事”“多行走”等继续保护。“行文”的保护改为可由已验证的行数量结构消歧，避免拦截“多行文本”。

结构证据保留原文词元位置及依赖关系，先完成读音裁决再生成发音文本。读音映射分别为边→编、和→河、行→航；这些替换用于合成器输入，原文位置注音接口仍返回边、和、行。

## 处理时机与接口限制

现有 `filter_speechSequence` 继续处理原始语音项并保护引号等信息。新增 NVDA 公开 `pre_speechQueued` 事件检查：它在原生语音词典和符号处理之后、进入合成队列之前，对尚未替换的和、边、邊、行再次裁决。已有的同音输出不再匹配这些目标，因此不会把它们重新解释为原字。修复范围限定在这些词边界和行列问题，未将全套语法在每个阶段重复执行。

这个事件接收可变的语音列表。插件先完成独立结果，再原位更新该列表；异常时保留原列表。所有命令对象、字符模式、开关、用户 keep 及规则禁用设置继续适用；不跨命令拼接上下文，不保留朗读内容，不新增人为停顿。

NVDA 及部分驱动会合并字符串，WorldVoice 也会处理中文空格，因此不能把拆成多个字符串或插入空格当作强制 token 边界。各合成器没有统一的外部 token 接口。本版采用“词元分析→读音裁决→明确同音文本→合成前检查”，并用实际合成结果验证；不宣称能关闭所有闭源合成器的内部切词器。

## 来源、验证与限制

继续使用固定快照的 [OpenHowNet](https://github.com/thunlp/OpenHowNet)、[CC-CEDICT](https://www.mdbg.net/chinese/dictionary?page=cedict)、[KFCD](https://github.com/kfcd/hyzd) 和 [cppjieba](https://github.com/yanyiwu/cppjieba)。新增语义类由构建脚本生成，原始输入哈希固定，许可证沿用既有声明。词典明确区分完整词 [唱和 chàng hè](https://dict.revised.moe.edu.tw/dictView.jsp?ID=124015)；不能把该词义推广到所有跨词边界的“唱”和“和”。

NVDA 时机依据本地固定版本的 `speech.speech.processText` 与 `SpeechManager.speak` 源码，并用实际队列入口测试词典新生成的三组文本及字符模式。WorldVoice 在语言检测前、后两种设置下测试其真实源码调用链。

语法回归共 1,154 例，其中本次新增 118 例，包含 106 个正例和 12 个反例；另有词元、生命周期、原文位置、设置、失败回退等测试。离线合成结果、基准耗时和包校验和以本版 artifacts 验收记录为准。

未提供名称的两个语音引擎无法逐一确认；测试范围会明确记录本机实际使用的引擎与声音。音频字节不同也可能来自韵律，不能直接断言为读音错误。未进行实时界面逐句听审，不保证开放域所有句子或所有声音都正确。
