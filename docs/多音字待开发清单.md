# NVDA 中文多音字待开发清单

版本：0.3（2026-09-05）
适用范围：NVDA 2026.2、简体中文普通话、桌面读屏和常见软件界面  
配套机器可读数据：`data/polyphone_inventory.json`；Ting-Ting 实机探测：`data/ting_ting_p1_probe_findings.json`

## 1. 先给出结论

这份清单不是一张“汉语所有多音字表”，而是**本插件在当前定义范围内的待开发清单**：优先收录桌面读屏中高频、能够由短上下文高置信判定、且错误读音会明显妨碍理解的词。姓氏、地名、文言、方言、诗词押韵读法和必须理解整句语义才能判定的项目另列，不会在默认模式下贸然改写。

当前人工工作清单共 **93 项**：P0 3 项、P1 39 项、P2 25 项、P3 26 项；其中默认规则涉及“行、重、盛、屏、弹”5 个目标字，“钥”仅为可选文读音偏好。“调试”已确认应读 tiáo shì，保留原文。除此以外，`data/unihan_polyphone_candidates.json` 整理了 Unicode 17.0.0 的 **8,181 个多读音候选字**：完整保留 kMandarin/kHanyuPinyin 来源字段，但全部处于未审核、未启用状态；其中有古音、地区差异、罕见读法，绝不能称作 8,181 个引擎错误。该大表仅用于离线研究，不进入插件安装包或朗读路径。[字段定义见 Unicode UAX #38](https://www.unicode.org/reports/tr38/tr38-38.html)。

用户新增的“盛”需要这样校正：

- `盛开` 应读 **shèng kāi**，其中“盛”与“胜”同音；如果语音读成 shèng，这一项本身是正确的。
- `盛汤、盛饭、盛水、盛粥、盛菜` 中的“盛”是“把东西放进容器”的动词，应读 **chéng**。
- 因此，实际缺陷是语音引擎把两种意义都按 `sheng4` 处理，而不是“盛开”也需要纠正。

当前优先级如下：

| 等级 | 含义 | 默认行为 |
|---|---|---|
| P0 | 用户已复现，或本机 Vocalizer 规则明确留下过同类修复证据 | 默认启用高置信规则并进入每个声音的音频回归 |
| P1 | 软件界面高频，适合固定词或局部模板 | 仅启用本轮确认需要干预的小集合；其余候选不改写 |
| P2 | 高频但真正依赖句法、词性或领域上下文 | 严格模式只处理明确上下文；其余保持原文 |
| P3 | 人名、地名、古诗、文白异读、口语变体或读音规范尚需复核 | 默认关闭，只列入人工听辨/专用配置 |

“默认启用”指在支持的语言和声音配置中启用规则，不等于不分引擎地强制换字。0.1.0 自动配置只匹配 `vocalizer_expressive2 / Ting-Ting`；其他声音默认 no-op，可手动选择实验性通用普通话同音字配置。程序不在线判断引擎是否已经读对；例如“重复”在某些原句中本就匹配正确音段，但仍会命中兜底规则。更精细的逐词 no-op profile 属于后续增强。

## 2. 规范和证据来源

读音规范以大陆普通话为目标，按以下顺序裁决：

1. 教育部、国家语委公布的[《普通话异读词审音表》（1985 年修订）](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201001/W020190416497956176438.pdf)。它主要解决“同一意义的异读”及统读问题，并不能代替多音多义词典。
2. 中国社会科学院语言研究所词典编辑室编《现代汉语词典》第 7 版。中国社科院说明该编辑室受国务院指示成立，承担《现代汉语词典》的编纂修订；商务印书馆称该书是以确定词汇规范、推广普通话为目的的规范型词典。[中国社科院介绍](https://ling.cass.cn/aboutus/zuzhijigou/cdbjs/202111/t20211112_5374315.html)、[商务印书馆书目说明](https://www.cp.com.cn/book/b11d8b3e-f.html)。
3. 商务印书馆《新华字典》第 13 版（2026）。第 13 版已于 2026 年 7 月出版；正式发布前仍须用正版纸书或 APP 对有争议条目逐项复核。[出版信息](https://www.cp.com.cn/Content/2026/07-26/1752310643.html)。
4. 教育部、国家语委 `GF 0030—2026` [《机器合成普通话水平测评等级标准及测评大纲》](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/202604/W020260407553212899124.pdf)。该规范自 2026-07-01 实施，适合作为后续合成语音人工评价的上位依据。
5. 开放数据只能用于“发现候选”和构造语料，不作为最终规范裁决。包括 [phrase-pinyin-data](https://github.com/mozillazg/phrase-pinyin-data)、[g2pW](https://github.com/GitYCC/g2pW) 及 [CVTE-Poly](https://github.com/NewZsh/polyphone)。这些资源本身也可能含错、含台湾读音或同时保留多种读法。

### 2.2 本机 Vocalizer 历史规则证据

本机文件：

```text
%APPDATA%\nvda\addons\vocalizer-expressive2-voice-zh-en-Compact\mnc_zh-CN\user_rules.txt
```

SHA-256：

```text
CC344217A3C5BFD4DA64EB36A8E59629291117C4AC00AFD82890B1D9011F151F
```

文件注释称其中一组为 `Chinese poem fixes - 07/08/2016`。它用同音字为“行、重、还、朝、长、得、传、载、荷、参、都、将、相、了、兴”等指定读音。这说明 Vocalizer 的中文前端长期存在上下文读音缺口，也证明“同音汉字替代”是该声库实际采用过的降级方案。

但该文件**不能直接导入插件**：

- 它主要针对指定古诗整句，不是现代 UI 通用规则。
- `行当浮桂棹` 被替换成“航当……”，疑似错误；这里“行当”是“即将”义，应读 `xing2 dang1`，不是 `hang2 dang1`。
- `斜→峡`、`衰→cuī` 等牵涉诗词押韵、古音与现代规范之争，不应覆盖普通文档。
- 个别条目是在修正文本文字或轻声，不属于多音字。

因此，本清单把它当作**缺陷发现证据和诗词回归语料**，每条仍需独立校对。

## 3. P0：已确认、首版必须完成

### 3.1 行：`xing2` / `hang2`

#### 默认启用的 `hang2`

- 固定 UI 词：`行首、行尾、行号、行数、行高、行宽、行距、行间距、行列、行标题、行标题和列标题、换行、空行、整行、逐行、多行、单行、同行同列`。
- 表格和文本行模板：`第 N 行、N 行 M 列、上一行、下一行、第一行、最后一行、当前行、每一行、一行代码、一行文本、两行内容`。
- 行业/机构义：`银行、分行、支行、总行、行业、行家、行情、行规、行话、行当（行业/职业义）`。
- 排行义：`排行、排行榜、排名行次`；用户要求的 `行二` 只有在“兄弟姊妹排行第二”或明确排行语境中才判 `hang2`。
- 成列义：`一行白鹭、儿女成行、两行泪`。

#### 必须保护的 `xing2`

- `行动、行为、行走、行人、行程、行驶、行政、行使、行文、可行、不行、进行、执行、运行、实行、施行、推行、履行、通行、流行、发行、旅行、步行、骑行、航行、品行、言行、修行、我行、此行、兵车行`。
- `一行人` 是“一群同行的人”，读 `xing2`，不能被“一行 + 名词”的模板误伤。
- `行当浮桂棹` 中的“行”是“即将”，读 `xing2`。
- `上行/下行` 在交通、网络和数据方向中通常读 `xing2`；`上一行/下一行` 才是 `hang2`。

#### 只做上下文判断

- `同行`：一起走/同业者分别可能是 `tong2 xing2`、`tong2 hang2`。
- `行二`：可以是排行，也可以出现在“再行二里、行二步骤”等被截断文本中。
- 单独一个“行”：上下文缺失时保持原文。

### 3.2 重：`zhong4` / `chong2`

#### 默认启用的 `chong2`

- 重复/再次执行：`重复、重新、重做、重来、重写、重播、重放、重发、重传、重试、重启、重开、重置、重装、重连、重排、重绘、重构、重建、重算、重选、重填、重输、重印、重录、重拍、重制、重修、重审、重测、重验、重述、重演、重返、重回、重现、重温、重获、重逢、重聚、重生、重组`。
- 层叠/复合：`重合、重叠、双重、多重、三重、N 重循环`。
- 固定专名：`重庆、重阳`。

#### 必须保护的 `zhong4`

- `重要、重量、重力、重心、重点、重视、严重、尊重、注重、看重、慎重、贵重、沉重、重任、重担、重伤、重兵、重音、加重、减重、承重、载重、重用、重判、重罚、重创`。
- `不重生男重生女` 的两个“重”都是“看重”，均读 `zhong4`；不能因为后接“生”就判为“再次出生”。

#### 必须做上下文判断

- `重读`：`把文章重读一遍` 为 `chong2 du2`；`这个音节要重读` 为 `zhong4 du2`。
- `重载`：软件“重新加载/热重载”通常为 `chong2 zai4`；交通工程“重载卡车/重载铁路”为 `zhong4 zai4`。
- `重装`：`重装系统` 为 `chong2`；`重装部队` 为 `zhong4`。
- `重名`：同名为 `chong2 ming2`；声望很高为 `zhong4 ming2`。
- `重犯`：再次犯罪者为 `chong2 fan4`；重要犯人为 `zhong4 fan4`。
- `重重`：`重重阻碍` 为 `chong2 chong2`；`重重地摔下` 为 `zhong4 zhong4`。

### 3.3 盛：`sheng4` / `cheng2`

#### 默认启用的 `cheng2`

- 固定动宾词：`盛饭、盛汤、盛水、盛粥、盛菜、盛酒、盛药、盛土、盛沙`。
- 有界模板：`盛 + 数量短语`，如 `盛一碗、盛两勺、盛半杯、盛一些`。
- 有界补语：`盛满、盛好、盛入、盛进、盛到、盛在、盛出来`，仅当“盛”表示装取/容纳时。
- 名词：`盛器` 读 `cheng2 qi4`。

#### 必须保护的 `sheng4`

- `盛开、盛大、盛会、盛况、盛行、盛产、盛世、旺盛、强盛、兴盛、繁盛、茂盛、盛名、盛情、盛夏、盛典、盛宴、全盛、鼎盛、盛装出席`。

#### 必须做上下文判断

- `盛装`：通常作为“华丽服装/隆重装束”读 `sheng4 zhuang1`；只有明确的装载动作语境才可能按 `cheng2` 解释。首版不得用“盛 + 装”泛化。
- 单独的 `盛` 或姓名中的 `盛` 保持原文。

### 4.1 2026-09-05 Ting-Ting 复核后的实机筛选结果

本机 Vocalizer 规则暴露出以下候选：

- `将进酒` 的“将”读 `qiang1`，只用于该古典固定词；`将要` 为 `jiang1`，`将领/飞将/将相` 为 `jiang4`。

- `参商` 的“参”读 `shen1`，是星宿名。

- `都邑`、`天都` 的“都”读 `du1`；“都已经”读 `dou1`。
- `了无、了可悟` 的“了”读 `liao3`。
- `兴尽、兴致` 的“兴”读 `xing4`。
- `行当浮桂棹` 的“行”应读 `xing2`；这是必须用来拦截错误 vendor 规则的负例。
- `乡音无改鬓毛衰`、`远上寒山石径斜` 等存在现代规范读音、古音押韵和吟诵习惯的冲突。教育部相关专家明确提醒，押韵读法不能简单等同于国家语言规范。[讨论与专家意见](https://edu.people.com.cn/n1/2019/0220/c1006-30807343.html)。这些项目只能进入“诗词朗诵 profile”，不得默认覆盖普通话正文。

### 6.3 口语或规范容许差异

以下只做听辨候选：

- `露出、露面、泄露` 的 `lu4/lou4`；
- `血` 的 `xue4/xie3`；
- `薄` 的 `bo2/bao2`；
- `熟` 的 `shu2/shou2`；
- `剥` 的 `bo1/bao1`；

## 7. 机器可执行规则的共同约束

### 7.1 读音 ID

内部 ID 一律使用无声调符号的 ASCII 音节加调号数字：

```text
xing2 hang2 zhong4 chong2 sheng4 cheng2
```

轻声记为 `5`，例如 `de5`、`le5`、`zhe5`。界面显示时再渲染为带调拼音，避免源码编码、查找和配置迁移问题。

### 7.2 命中优先级

```text
用户明确覆盖
> 禁止改写/反例
> 专名白名单
> 最长固定词
> 软件领域短语
> 有界结构模板
> 高置信句法规则
> 保持原文
```

### 7.3 不允许的泛化

- 不能用 `重 + 动词 = chong2`；`重视、重用、重判、重罚、重创` 都是反例。
- 不能用 `一 + 行 = hang2`；`一行人、一行三昧` 都可能不是行列义。
- 不能用 `盛 + 名词 = cheng2`；`盛会、盛世、盛情、盛夏` 都是反例。
- 不能用 `数量 + 场 = chang2`；`一场会议、一场比赛` 中量词读 `chang3`。
- 不能用 `长 + 名词 = chang2`；`长大、长高、长官` 是反例。
- 不能把二字串当作永远同一词；例如“长相忆”不是“长相”。

### 7.4 分段时停手

如果 NVDA 的 `SpeechSequence` 在目标字和判定上下文之间插入了语言、字符拼读、索引、停顿或格式命令，默认不得跨越命令猜测。0.1.0 连相邻字符串也不合并，保留原分块；合并透明片段只作为后续研究。上下文丢失时，漏修优于误修。

## 8. 回归语料最低集合

- 10 个应修正正例；

## 9. “完整清单”的版本化定义

在这个项目里，“全部整理”应定义为：

1. 当前支持范围内发现的每个候选都有唯一 ID；
2. 有规范读音、正例、反例、风险等级和状态；
3. 已区分“语言规则正确”与“某个语音引擎确实读错”；
4. 每次新增用户报告，都先进入 `reported`，经过词典校对、文本测试和声音听辨后才进入 `verified`；
5. 未通过高置信门槛的项目保留在 P2/P3，而不是为了表面覆盖率强制纠正。

汉语的实际文本、专名和新术语不断增长，所以不能诚实地承诺穷尽所有汉语多音字；本清单按明确范围保持可追踪、可复现、可扩充，目标是尽量减少误改。有限规则仍可能遇到未收录的跨词反例，不能宣称“零静默误改”。
