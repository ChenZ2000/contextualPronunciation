# 0.4.0 数据审查与覆盖扩展

本版延续 0.3.0 的全局语音策略，重点是补足数量语境、严格区分字位缺证与整词歧义，并建立可复现的读音覆盖清单。不是“汉语所有语境已经完成”的声明。

## 用户提供的 cc-table 适合怎样使用

已检查 [go-cc/cc-table 的常用多音字表](https://github.com/go-cc/cc-table/blob/4585fd963d27cb4311fff92ea6438bdae0089ce3/text/info/duoyinzi/常用多音字表.md)。固定提交为 `4585fd963d27cb4311fff92ea6438bdae0089ce3`，Git 原始文件字节 SHA-256 为 `07c0b8f323373364c62ec9c0b24a8012c61eea38255b628b3a53f02a11a4340a`。Windows 工作树可能转成 CRLF，所以审查脚本读取固定 Git 对象，而不是依赖换行格式。

它是按字列读音、例词的参考表，不是整句消歧模型。存在错行、目标字与例词不对应、错误拼音和缺失条目。例如“方便、便利”被列到“辟”下，“伺机”的读音写成 `chuo`。教育部《国语小字典》的[“伺”条目](https://dict.mini.moe.edu.tw/SearchIndex/word_detail?breadcrumbs=Search_%E4%BC%BA_one&dictSearchField=%E4%BC%BA&wordID=D0002571)可以独立核对后者应读 sì。

仓库声明 [MIT 许可](https://github.com/go-cc/cc-table/blob/4585fd963d27cb4311fff92ea6438bdae0089ce3/LICENSE)，文档另标 `xh.5156edu.com/page/18317.html` 为来源，本次未取得该转载链的充分出处说明。因此不将整表作为已核实的运行数据分发。仓库留在开发目录 vendor，逐条提取报告留在 artifacts，两者均不打入发布包；已经开放授权的 CC-CEDICT、KFCD 与 Unihan 数据继续作为可复现编译输入。

机器可以提取 263 个不同目标字、580 条读音声明、940 个例词检查项：

| 检查分类 | 数量 | 如何处理 |
|---|---:|---|
| 与现有 CC-CEDICT 目标字音一致 | 574 | 只是交叉印证的候选，不能等同任意句子可替换 |
| 目标字音与 CC-CEDICT 不一致 | 14 | 人工查证，不自动选一方 |
| CC-CEDICT 含专名阻断或整词多读音 | 54 | 保留歧义 |
| CC-CEDICT 没有这个精确词头 | 170 | 待补词语证据 |
| 固定 Unihan 字段未收录该字音 | 52 | 可能错误或来源范围不同，不直接判错 |
| 字与例词不对齐或目标重复 | 72 | 人工检查排版和目标位置 |
| 一行混入多个读音编号 | 8 | 不猜测错行修复 |

以上是受原表排版限制的机器提取统计，不是完整人工校订，也不是原表的错误率。不能以“多数条目一致”批准整表自动导入。它仍有价值：帮助发现需要进一步查证的字和语境，而不是成为不加筛选的优先规则。

## 新增行数量和竖排语境

新增 `rowIndefiniteQuantity` 有界结构规则，支持几行、幾行、数行、數行、若干行、多少行、十几行、二十多行、百余行等。允许最多四个行内空格，不跨换行、命令、独立语音片段；数字上限仍为十二位。

“这几行很好”的行可在句中判为 háng，不依赖后面有没有标点。“竖行／豎行／竪行”加入同一排版词组族。行作为排列单位并不限于现代电子表格的横排，见[教育部《异体字字典》行条目](https://dict.variants.moe.edu.tw/dictView.jsp?ID=40255&la=1)。该辞典另收历史、地域读音，不能不加区分地用于现代大陆普通话。

反例包括“茶几行不行”“这张茶几行吗”“这个参数行吗”“约数行吗”“数行程”“一行人”“横行霸道”“直行车辆”。家具“几”的左上下文不会被当成不定数量；“数／數”需独立数量、写了／删除／共有等计数上下文，或明确行内容词作证，避免参数、读数、约数等名词尾部误触发。明确的行走、行礼、行善等词义仍由保护规则优先处理。“这几行不行”仅前一个行是 háng，后一个是表示可行性的原字，不把两个行同时替换或同时保护。模糊文句、专名和省略上下文不能据此宣称已经完整理解。

屏息、屏气凝神、弹琴、弹奏、弹唱、弹簧、弹性、弹力使用现有读音映射和保护机制，没有增加新语音后端。例如“子弹性能很好”的“弹”不会被内部“弹性”覆盖。其读音依据来自现有固定字典和字音资料，不从 cc-table 的错误条目推导。

## 字位缺证不等于整词歧义

旧编译器在某字音没有 Unihan 交叉证据时，将整个词变为空阻断。本版保留已经对齐并得到确认的其他字音，把缺证字位写为 `?`；不填默认音，也不围绕未知字位拆词。

但必须保留三类整词阻断：专名风险、同词多读音、涉及轻声默认字的语法消歧。开发时负例实际发现，若把第三类也逐字放行，会把“文中的词语”“手中的书”中的“中”误读成 zhòng。这是“中的”可能表示命中目标，也可能只是短语的一部分，不能只靠去掉“的”的注音消除歧义。因此语法风险仍整词弃权，并有专门回归，未以误读换取覆盖统计。

最终运行词头仍为 110,692 个：89,550 个可提供全部或部分注音，21,142 个保持阻断；较 0.3.0 新增 140 个部分注音词头。894 个多读音目标字、448 个符合语音候选政策的字、4,801 个含可渲染非默认读音的词头，都是候选规模，不是实际误读修复数量。

## 完整的固定来源清单，而不是虚假的全场景支持

`data/polyphone-coverage.json` 列出 Unihan 17.0.0 的 kMandarin、kHanyuPinyin、kTGHZ2013 字段规范化后具有多个读音的所有字：8,372 个字、19,570 个字音组合，其中 2,587 个字出现在 kTGHZ2013 字段中。字段定义见 [Unicode UAX #38](https://www.unicode.org/reports/tr38/tr38-39.html)。包含历史、地域、姓氏及异体读音，不能称为“现代常用多音字有八千多个”。

每个字音都有词头计数、最多五个词例、审阅规则 ID、同音映射候选与状态，四类状态分别是已有审阅语境、扩展词典候选、仅有注音证据、仍需上下文证据。存在词例也不保证能在每个长句中稳定分词。

贡献者可以执行：

```powershell
python tools/build_polyphone_coverage.py --query 行
python tools/build_dictionary_database.py --query 词语
python tools/pronunciation.py "这几行很好，竖行"
python tools/pronunciation.py --check-contributions
python tools/import_cedict.py --check
python tools/build_polyphone_coverage.py --check
```

先查缺口与来源，再补正反例和有界模板；词典整词匹配、结构规则、自定义模板继续使用原有统一裁决，不建立平行引擎，也不引入在线模型。清单只随源码提供，不进入 NVDA 的同步朗读路径。运行词头目前仍采用原始简体词头，不把繁简一对多关系强行转换。

参考表的可选开发审查命令为：先将指定 cc-table 提交克隆到 `vendor/cc-table`，然后运行 `python tools/audit_polyphone_reference.py`。它只生成诊断报告，不修改运行词库；不是发布时需要联网下载的依赖。

## 盲文与验证

国家通用盲文 2018 可选输出表使用现有已审阅省调读音，增加到 439 个固定上下文，含 231 个纠正和 208 个保护。竖行有原生 Liblouis 点位与光标路由测试；“屏息”等基表已有整词条目保留基表路由，不假装每个字都能单独路由。

动态数量规则通过原文注音 API 可用，但不会被不加约束地编译成静态盲文表。数量语境、扩展词库、自定义配置到国家通用盲文的完整分词连写与动态路由，仍不是本版已经完成的功能。共享注音从不使用语音替代汉字作为盲文输入。

发布工作流新增覆盖清单复现检查、全部字音清单测试、新数量语境与语法反例、Unicode 边界、新语境性能场景及八组 VE 声学锚点。仍执行固定 NVDA 2026.2 源码构建、官方单元测试、实际安装的 WorldVoice 6.2 管线回归和原生 Liblouis 回归。最终运行结果、版本和包校验值以 artifacts 下的 release-verification.json 与 workflow-report.json 为准，本文不预先宣称未执行的检查通过。

0.3.0 的 WorldVoice 活跃实例已获用户试听确认；不能据此把 0.4.0 的所有新增上下文或其他声音标为人工验收完成。
