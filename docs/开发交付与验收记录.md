## 2. 已实现能力

1. 公开 `speech.extensions.filter_speechSequence` 注册和对称注销；不 monkey-patch NVDA、符号处理器或语音驱动。
2. 按目标字和左右邻字索引的固定词桶，有界数字/行列/排行/盛取数量扫描。支持“第 12 行”“12 行 8 列”“行：12”“盛半碗”等；不做在线分词、模型推理或网络查询。
3. 读音 ID 与声音实现分离。自动只匹配 VE2 Ting-Ting；未知声音 no-op；通用普通话同音字配置需用户主动选择。
4. 同时检查 NVDA 有效语言与实际声音语言，镜像 NVDA 的自动语言切换及同语根方言折叠设置；英语、粤语和未验证的 zh_TW 不使用普通话替换。
5. 字符/拼读模式旁路；命令对象、顺序、索引和分块保持；不跨字符串或命令合并上下文。
6. 词内 ASCII/Word 弯撇号保留，mandatory 符号元数据复用已有 identifier；非词内右引号 guard 保持“全部符号”的报告能力。
7. 简体中文设置与帮助；设置即时生效、配置档切换刷新；总开关、中文开关、弯撇号开关、严格模式及声音配置。
8. 有界用户 force/keep 和按 ID 禁用；用户规则优先。设置保存前校验，启动/设置变更时编译，热路径无文件访问。配置无效时中文改写关闭，原文继续朗读。
9. 异常返回原序列；限速且不主动记录朗读原文的诊断日志；无原文缓存、遥测、更新网络请求或后台线程。
10. 可重复构建、源码导出、回归和证据哈希一致性核验。

## 3. 读音审核结论

默认处理“行、重、盛、屏、弹”的有限高置信上下文；不能理解成单字全局替换。

- 行首、行尾、行列数量和排行义：háng；行为、一行人、步行等保护原文。
- 重复、重新、重试：chóng（二声）；重要、体重、重读音节等保护原文。某些“重复”原句在 VE 中本就读对，插件并不在线探测每次是否需要干预。
- 盛汤、盛饭、盛半碗：chéng；盛开 shèng kāi 本来正确，不改。
- 屏住呼吸：bǐng；屏幕类词保护原文。
- 回弹、弹出、弹窗：tán；炮弹、子弹、中弹等保护原文。
- 密钥/公钥/私钥的 yuè 是可选文读音偏好，严格模式不启用，不计入确定错误。
- 调试：tiáo shì。早期 gold label 的 diào 已纠正，并移除调→吊规则、加入防复发测试；原音段在本机测试中正确。[三菱电机公开技术术语表](https://www.mitsubishielectric.com/fa/service-support/global/fa_dictionary/pdf/TD0002.pdf)也将调试/debug 标注为 tiáo shì。

人工候选清单还纠正了“数次”shù cì、“少年/少女”shào 等标注，并对“标识”保留多读音义项，不把一个读法统判为错误。广义 Unihan 数据含古音、地区差异和罕见读音，必须经过规范及语境审核后才能进入运行规则。

## 4. 已运行的自动测试

`python -m unittest discover -s tests -v`：**76 项通过、0 失败、0 跳过**（最终机器记录另见 `artifacts/release-verification.json`）。其中的参数化循环还覆盖多个正反例；76 是测试方法数，不是全部句子数。

测试内容包括：原对象快速返回、命令对象与顺序、字符模式、语言切换、实际声音切换、方言折叠、反例优先、数字扫描上限、未知读音/格式错误拒绝、用户覆盖与禁用、设置及配置档刷新、生命周期、真实 NVDA 符号处理、翻译、打包布局和可重复构建。

真实 `SpeechSymbolProcessor` 来自本地固定的 NVDA 2026.2 源码，en/zh_CN/zh_HK/zh_TW 内置符号数据与插件字典一起参与测试。GlobalPlugin 的集成测试加载真实插件代码，但 NVDA 配置、wx 和语音对象为桩；不是已在真实桌面 UI 中完成安装运行的声明。

## 5. VE 离线声学证据

环境：当前安装的 `vocalizer_expressive2_driver` 2026.6.6；Vocalizer 产品版本 2.2.0，build 2016-06-29；Ting-Ting Compact。本机 NVDA 继续运行，没有安装开发包或修改其配置。

| 验证 | 规模 | 自动结果 | 限制 |
|---|---:|---|---|
| P1 多音字探测 | 39 字、178 原词、574 个原词/锚渲染 case | 76 预期音段匹配、4 明确音段不符、86 声调不可判、8 实验锚匹配、4 文白读音偏好差异 | `usPhoneme` 不编码普通话声调；不能把声调不可判当作读对 |
| 最终运行规则输出 | 11 组、33 条文本；10 默认组、1 可选偏好组 | 11/11 完整音素序列及整段 PCM 与独立同音锚相等 | 证明固定环境内输出相同，不替代人耳判断、语料精确率或全声音认证 |
| 英文 apostrophe | Samantha、Allison、Serena，各 23 条 | ASCII 与 Word U+2019 的 Doesn't/Mike's 样例音素和 PCM 相同；U+02BC 的 Doesn't 退化为无撇号形式 | 直接引擎输入测试，不包含 Word 将一个单词切成多个块的情况 |

探针在独立 Python 进程加载本机引擎，只接收 PCM 回调写 WAV，不创建音频播放器，不发声，不写入 NVDA 或 add-ons 目录。调用的是真实本机 DLL，不是用文字替换结果假装听到了语音。

证据：`docs/Ting-Ting-P1多音字实机探测报告.md`、`artifacts/final-renderer-regression-summary.md`、`artifacts/vocalizer-apostrophe-probe-summary.md`。原始 WAV、marker、完整音素与 PCM SHA 在相应 artifacts 子目录。

## 6. 实测处理耗时

Python 3.13.5 / Windows 11，短样例每轮 100,000 次、长样例每轮 2,000 次、共 7 轮。以下数字是“每轮批量平均耗时”的中位数，不是单次延迟分布的 p99。

| 场景 | 码点数 | 耗时 |
|---|---:|---:|
| 纯处理器，无候选 | 12 | 0.50 微秒 |
| 真实插件 Filter，NVDA 属性为内存桩，无候选 | 12 | 1.78 微秒 |
| 同上，典型 P0 命中 | 24 | 15.49 微秒 |
| 同上，典型 P1 命中 | 21 | 9.01 微秒 |
| 纯处理器，词内 apostrophe | 22 | 3.42 微秒 |
| 纯处理器，长文本无候选 | 8,125 | 0.208 毫秒 |
| 纯处理器，长文本稀疏命中 | 8,175 | 0.860 毫秒 |

不含真实 NVDA 分发、COM/IPC、语音合成、音频设备、首音和取消延迟。可以据此说明同步处理成本很低，不能声称“数学零耗时”或“实际读屏端到端完全无影响”。原始报告含测量方法、源码 SHA 和各轮最小/最大批量均值，见 `artifacts/performance-report.json`。

- 未声学认证其他中文声音或不同声库质量；自动配置匹配驱动名/voice 名，并不会自动证明未来升级的同名声库仍有相同输出。
- 不处理已经被上游切开的 token、孤立多音字、未知姓氏/地名及一切歧义；键入单词回显要走 NVDA core 的独立修复。

这些限制已写入随包帮助。预览版代码和自动验证已完成；上述待验收项没有被标记为通过。
