# 0.7.1：数量结构、词法证据与“将”的名词角色

本轮由用户提供的“重吸收、盛了一碗饭、重捏、重飞、虾兵和蟹将、天兵和天将”驱动。
它们进入测试语料，没有作为整句规则写入运行时。0.7.0 已能处理重捏、重飞；本轮将这两项也固定为回归与声学样例。

## 词法证据分级

`grammar_lexicon.json` 的 357,293 个词头和 82,381 个动词候选来源未更换。
原来混在一起的 1,199 个重字阻止条目分为 396 个明确冲突或读音不可靠的条目，以及 803 个只有分词/POS 记录、没有读音的条目。
明确冲突仍优先。只有整个后接成分是至少两字、至少两个来源支持、没有名词/形容词等竞争词性的完整动词时，才能覆盖后一类阻止。
因此“重吸收”可从“重＋吸收”得到 chóng；“重酬”等只有单字或弱证据的条目仍保留原字。
这不是把所有动词前的重强制读 chóng，也没有移除重视、重用、重罚、重读、重载等词义保护。

## 数量短语与词义选择

OpenHowNet 的 classifier 义项提供 29 个容器量词、15 个人员量词；noun 义项提供 313 个军队/军人名词和 8,560 个人物名词候选。
编译器保留可追溯的词头，运行时不读释义。繁简词形只沿来源明确、唯一的整词对应传播，不做任意逐字替换。

分词在数量位置保留 `数词＋形容词？＋量词` 分析，解决一碗、一大、小碗、盆汤、一杯等词典条目吞掉语法成分的问题；三明治、八宝粥等实词仍保留。
成分分析生成 `nummod` 和 `clf` 关系。容器量词只对它实际修饰的名词中心选择食物/材料义，不向定语中相邻的食物词借用证据。
“盛了一大碗刚煮好的饭”的中心是饭；“盛了一碗饭的价格”的中心是价格，不应改成 chéng。
结果补语与体标记组合由同一层生成：例如“盛出了、盛满了”无须登记整句。

## 名词角色与并列

新增 `nominals.py`，通过 `NP(军队/军人)＋连词＋NP(修饰语、将)`、逆向并列，以及直接修饰将的人员量词，判断将为名词 jiàng。
虾兵和蟹将、天兵和天将、蟹将和虾兵、一员守卫边关的将使用同一组产生式。
完整名词短语必须通过已有成分分析；关系保留原文偏移，语音裁决和动态注音 API 共用结果。

不能仅因句中有兵就选择 jiàng。“士兵和飞机将起飞”“老师将和士兵离开”仍有助动词解释，必须保留原字。
未带明确名词标记的“虾兵和蟹将出发”“天兵和天将都在门口”也可能被保守保留；这里的保留并不等于断言 jiāng 正确。
“那些训练有素的士兵和身经百战的将都已经来到门口”有明确修饰结构，可以判断名词。
将军、将来、将近、将就等完整词不被拆出名词将；用户 keep、禁用规则和逐字模式仍优先。

## 验证与复现

`tests/grammar_cases.py` 包含 737 个去重后的定向案例：621 个目标读音、116 个保留原字案例。
0.7.0 原来的 105 例全部保留；新增 632 例。交叉变化涵盖动词、语境、体标记、量词、形容词、嵌套定语、中心词、并列顺序、连词、繁体和反例。
预期读音由人工确定，测试生成器不调用运行引擎来生成答案。这个规模是结构回归覆盖，不是开放文本准确率。
原句含两个将的完整文本另逐位置检查，避免只检查第一个目标。

```powershell
python tools/build_grammar_data.py --check
python tools/evaluate_grammar.py --baseline dist/contextualPronunciation-0.7.0-source.zip --output artifacts/feedback-baseline-comparison.json
python -m unittest tests.test_feedback_grammar tests.test_compositional_grammar
python tools/benchmark_grammar.py
```

额外检查公开 NVDA 语音过滤器、真实 WorldVoice 源码的两种语言检测顺序、原始字符/UTF-16 偏移、命令分段、用户覆盖与工作预算。
新增九组独立同音锚点用于 Ting-Ting 离线音素/PCM 对照；完整发布流程必须重新渲染，不能复用旧音频报告。

分析仍受 512 字、256 词、递归深度及工作预算限制。新增机制是可审计的符号句法和词义选择，并非通用语义模型；省略、未知词、比喻、指代及歧义可能保留原字或误判。
没有新增原生 DLL。性能门槛未放宽，基准增加数量短语、并列名词和密集/异常名词输入；具体发布结果见 artifacts 中当次报告。
